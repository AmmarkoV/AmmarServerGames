# FRISK

FRISK is a browser-played, asynchronous, LAN-hosted Risk-like board game built
as an AmmarServer C service.  Its default data pack is the owner's *RISK: The
Lord of the Rings* board with the rules in `PLAN.md`.

## Build and run

FRISK is built from the parent `AmmarServer` checkout (the game repository is
included as a subdirectory):

```sh
cd /path/to/AmmarServer
cmake -S . -B build
cmake --build build --target frisk -j
src/AmmarServerGames/frisk/frisk
```

Run it from the AmmarServer root because the defaults for the web root and the
shared account database are relative paths:

| Variable | Default | Meaning |
|---|---|---|
| `FRISK_PORT` | `8090` | HTTP port |
| `FRISK_RES_ROOT` | `src/AmmarServerGames/frisk/res/` | SPA, maps and static assets |
| `FRISK_DATA_DIR` | `db/frisk` | game state/logs and chat logs |
| `FRISK_USERS_DB` | `db/users.db` | shared AmmarServer account database |
| `FRISK_CLIPS_DIR` | `res/uploads/clips` | voice clips |
| `FRISK_CLIP_CAP_MB` | `256` | housekeeping cap; `0` disables the cap |
| `FRISK_FINISHED_TTL_SECONDS` | `86400` | how long a finished game stays loaded after its last save |

Open `http://<host>:8090/`.  The client is dependency-free; no CDN or build step
is involved.

AmmarServer keeps the static files in memory and sends them with
`Cache-Control: max-age=3600`.  After changing anything under `res/`, restart the
server, and bump the `?v=` tag on the CSS/JS links in `res/index.html` so browsers
fetch the new files as a matching set instead of mixing cached old ones in.

## Accounts, invites and administration

The first account registered on a fresh `db/users.db` becomes the administrator
and does not need an invite.  Every later account needs an invite code; any
signed-in player can mint one from the lobby account panel.  Accounts are shared
with other AmmarServer services that use the same database.

Administrators also get an **Admin** link in the top bar (`#/admin`).  It shows
users, invite codes, games and storage use, and can revoke invites, delete
games, or neutralise an abandoned seat.  The neutralise action is only allowed
during a running game's reinforce/attack/fortify phases; delete the game for an
abandoned setup.

## Data and backups

The canonical durable data is:

- `db/frisk/games/game_<id>.json` — current game state (bounded event ring)
- `db/frisk/games/game_<id>.log` — append-only JSONL event history
- `db/frisk/history.log` — one JSON line per finished game (profile history)
- `db/frisk/chat/<room>.log` — lobby and game chat
- `res/uploads/clips/<token>.<ext>` — voice clips
- `db/frisk/profiles.db`, `invites.db`, `remembers.db` — account-side FRISK data
- `db/users.db` — shared AmmarServer accounts

Back up all of `db/frisk`, `res/uploads/clips` and `db/users.db`.  Clips live
under the web root because AmmarServer's file streaming refuses paths outside
it; names are 22-character random base64url tokens.  `/api/clip` requires a
signed-in session, but the token URL is also reachable through the static file
server, so treat it as an unguessable link rather than a private ACL.

## Map packs

A pack lives in `res/maps/<name>/` and contains `map.json`, the referenced board
image/SVG and any sprite files.  Validate a pack with:

```sh
src/AmmarServerGames/frisk/build/mapcheck res/maps/<name>
```

The LOTR pack is generated by `frisk/tools/mkmap.py`.

## HTTPS and microphone recording

FRISK works over plain HTTP.  On a phone, the microphone button opens the
system recorder through `<input type="file" accept="audio/*" capture>`, so
clips upload normally without HTTPS.  In-page hold-to-record
(`MediaRecorder`/`getUserMedia`) and desktop notifications require a secure
context.  See the parent `AmmarServerGames/README.md` for the OpenSSL build and
self-signed-certificate startup command.

## Tests

```sh
src/AmmarServerGames/run_tests.sh
```

This runs the engine/unit/fuzz suite, the HTTP smoke test, the authorization
audit, `tests/history_test.py` (finished-game history, unloading and faction
switching) and `tests/browser_input.py`, which drives headless Chrome with real
mouse/touch/keyboard events (map clicks, drag, pinch, double-click zoom and
placement).  The browser test skips itself when no Chrome/Chromium binary or
Python `websockets` module is installed; `FRISK_CHROME` selects the browser.  Additional longer checks:

```sh
cd src/AmmarServerGames/frisk
python3 -I tests/long_game.py --turns 2000
python3 -I tests/load_test.py --seconds 600 --pollers 20 --actors 4
```

The long-game test drives 2,000 turns through the HTTP API on a generated
8-territory pack.  The load test starts an isolated server and checks that 20
polling clients plus four acting clients leave descriptors and memory stable.

For the server under AddressSanitizer/UBSan, run from the AmmarServer root:

```sh
cmake -S . -B build-sanitize -DFRISK_SANITIZE=ON
cmake --build build-sanitize --target frisk -j
ASAN_OPTIONS=detect_leaks=0:halt_on_error=1 \
UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1 \
  FRISK_SERVER_BIN=$PWD/src/AmmarServerGames/frisk/frisk \
  src/AmmarServerGames/frisk/tests/http_smoke.sh
```

## Authorization matrix

All POSTs require a signed-in session and a CSRF field except login/register.

| Endpoint | Anonymous | Signed-in player | Seated player | Admin |
|---|---|---|---|---|
| `GET /`, `/api/map`, static assets | yes | yes | yes | yes |
| `GET /api/me`, `POST /api/login`, `POST /api/register` | yes | yes | yes | yes |
| `POST /api/logout` | no | yes | yes | yes |
| `/api/invite/new`, `/api/profile`, `/api/profile/set` | no | yes | yes | yes |
| `GET /api/invite/list` | no | own invites | own invites | all invites |
| `POST /api/invite/revoke` | no | own invites | own invites | any invite |
| `/api/lobby`, `/api/chat`, `/api/clip` | no | yes (read) | yes | yes |
| `/api/chat/say`, `/api/chat/clip` | no | lobby only | lobby + own game | lobby + own game |
| `GET /api/game/state`, `/api/game/log` | no | yes (spectate) | yes | yes |
| `POST /api/game/act` | no | no | own turn / legal action | own seat rules |
| `/api/game/create` | no | yes | yes | yes |
| `/api/game/join`, `/api/game/leave` | no | open games | open games | open games |
| `/api/game/start` | no | host only | host only | host only |
| `/api/game/kick` | no | host only | host only | yes |
| `/api/game/delete` | no | host, non-running | host, non-running | any game |
| `/api/admin/overview`, `/api/admin/neutralise` | no | no | no | yes |

Game chat is readable by spectators but only seated players may post.  Clip
reads require login; filenames are validated as a single random token plus one
lowercase extension.

## Keyboard and accessibility

In a game, desktop users can press `Enter` to activate the marked primary
action (done reinforcing/attacking, end turn, move, start), `Esc` to clear the
selection, skip a replay or close an open panel sheet, and `1`/`2`/`3` to attack
with that many dice when a legal attack pair is selected.  Double-click (or
double-tap) a territory to zoom to it.  Clickable territories have a pulsing
white ring on their army badge; the chosen source is cyan and the target orange.
Hovering (or tapping) a territory shows its name, region bonus, owner, armies,
leader, stronghold and site; the Players tab lists every region with its bonus
and holder.  With *Sound effects* on, a short chime plays when a game turns to
you (desktop notifications need HTTPS).  On portrait phones the turn controls dock
at the bottom and Players/Cards/Log/Chat open as sheets over the map.  Focus outlines are visible, faction fills use
distinct stripe/dot/hatch patterns as well as colours, and the CSS honours
`prefers-reduced-motion`.
